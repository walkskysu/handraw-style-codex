# IdeaCanvas

使用 **Vue 3 + TypeScript + Vite + Tauri 2** 搭建的手绘风格生图工作台。
输入提示词，选择快速单图或先规划再确认，应用调用本机 Codex CLI，逐张预览并保存图片。

## 快速生成与规划生成

描述标题右侧的「快速生成」开关默认开启，每次固定生成一张独立图片，并记住上次选择的模式；关闭后进入规划生成。
「规划生成」支持自动决定或指定 1–12 张；指定数量优先于描述中的数量。先点击「生成计划」，查看每张的文案、画面、共同视觉配置和核查说明，再明确确认。反馈产生完整新版本；修订失败保留旧版与反馈。修改输入或配置后，旧计划失效；未应用的反馈也会阻止确认。

确认后立即出现固定序号的任务位置，每张完成即可查看和独立入库。默认跟随最新结果，手动选择后停止跟随；可用方向键浏览。一次只执行一个模型任务，切换到图库不终止生成。「停止后续生成」会完成并保存当前图片，再停止；单项失败可独立重试，保存失败只重试现有字节。登录失效或未知错误会暂停队列。

「草稿与任务」可找回历史计划、未完成或全部失败的任务。重启不会自动调用模型，用户选择继续后才恢复尚未完成的位置。成功图片不会重新执行。确认计划与实际提示词随组导出，历史版本不会被覆盖。

## 检查和安装更新

桌面应用启动 5 秒后自动检查 GitHub Release；发现新版本时显示非弹窗提醒。
也可打开「设置 → 关于 IdeaCanvas」查看当前版本、新版版本号和更新内容，并手动检查更新。
「稍后提醒」会在本次运行一小时后再次提醒，下次启动也会重新检查。

点击「下载更新」后显示下载进度，更新包通过内置公钥的签名校验后才显示「重启并安装」。
下载的已校验安装包仅保留在本次运行内存中，重开应用需重新下载。点击安装时若正在生成或导出，
会等待任务结束；如图库保存失败，请关闭设置，在作品预览中重试保存，成功后自动继续安装。
等待期间暂停新图片生成，也可在设置中取消自动安装。安装失败会恢复创作入口，并提供「重新下载」和「手动安装」。
如果安装程序退出或取消后仍启动旧版，会提示上次更新未完成。手动安装会打开官方 Release 页面，安装前请先保存作品并关闭应用。

更新源为 `https://github.com/walkskysu/handraw-style-codex/releases/latest/download/latest.json`。
Release 必须发布为正式版本（草稿/预发布不会成为 latest），包含 `latest.json`、Windows x64 NSIS 安装包和 `.sig`。
沿用 `src-tauri/tauri.conf.json` 的公钥及现有 Actions 签名密钥；不要把私钥放入仓库。
`latest.json` 的 `notes` 作为纯文本展示，因此发布时需填写实际更新内容。
支持清单中的 `windows-x86_64-nsis` / `windows-x86_64`，以及 GitHub API asset 下载地址；
Tauri updater 下载时使用 `Accept: application/octet-stream`，下载和安装均校验签名，并要求清单版本与签名中的版本一致。
插件安装 IPC 不直接授权给前端，安装只能经过应用的生成/保存保护命令。

桌面发布验收：用同一签名密钥发布更高版本，在旧版检查 → 下载 → 生成中预约安装 → 确认作品保存后重启；
同时验证断网、错误签名、保存失败、取消等待和取消安装后重开旧版的恢复入口。自动测试不会启动真实安装程序。

## Windows 环境准备

仅运行前端和前端测试需要 **Node.js 22.12+（推荐 Node.js 24 LTS）及 npm**。
开发或构建桌面应用还需要：

1. [Microsoft C++ Build Tools](https://visualstudio.microsoft.com/visual-cpp-build-tools/)，勾选「使用 C++ 的桌面开发」及 Windows SDK。
2. [Rust](https://www.rust-lang.org/tools/install)，使用 stable MSVC 工具链（通常为 `stable-x86_64-pc-windows-msvc`）。
3. [Microsoft Edge WebView2 Runtime](https://developer.microsoft.com/microsoft-edge/webview2/)，Windows 10/11 通常已安装。

完整说明见 [Tauri 官方前置依赖文档](https://v2.tauri.app/start/prerequisites/)。安装后重新打开 PowerShell，确认 `node --version`、`cargo --version` 和 `rustc --version` 可以执行。

## 本地运行

在项目根目录打开 PowerShell：

```powershell
git submodule update --init handraw-style
npm.cmd ci
npm.cmd run tauri -- dev
```

Tauri 自动启动 Vite 并在屏幕正中央打开桌面窗口。输入画面描述后点击「生成图片」或「生成计划」，状态与错误显示在计划和作品区域；可从「草稿与任务」恢复任务。

### 选择手绘风格、排版图型和主题色

IdeaCanvas 工作台采用暖白背景、墨绿按钮和两栏布局：左侧输入「你想画什么？」并设置可选的画面偏好，右侧宽区域浏览灵感图鉴。顶部提供「创作 / 我的图库 / 草稿与任务」。生成入口固定在创作区底部，提交后自动打开独立的计划与作品面板；关闭面板不终止任务，重新生成或失败时保留上一张作品。

工作台固定在窗口内，不显示应用外层滚动条。灵感图鉴的风格、排版、主题色内容在各自标签内滚动，标题和类别标签保持可见；搜索或切换类别后回到内容顶部。小窗口中的创作区和预览面板仍可滚动访问，窄屏上下排列时在工作区内滚动，图鉴保留独立滚动区域。

图鉴通过「风格 / 排版 / 配色」标签提供 **366 种手绘风格、170 种排版图型、36 种经典单色主题色**。每类先显示 40 项，通过底部「加载更多」每次追加 40 项，图片按需懒加载；搜索覆盖整个类别，搜索或切换类别后恢复首批。共用一个按编号、名称或分类搜索的输入框。点击卡片立即选中，左侧三行偏好同步显示所选编号，悬停可查看名称。每类最多选择一项；默认全部不选，点击左侧的「×」可单独清除，切换类别、滚动、搜索和失败重试都会保留选择。

点击左侧配置可切换到对应类别并滚动定位已选卡片（同时清空搜索）。所有桌面宽度均显示创作与图鉴双栏，通过顶部「草稿与任务」打开独立面板，入口同时显示处理状态；小于 640px 时创作区与图鉴上下排列。定位已选卡片时会自动加载所需批次。预览面板可通过关闭按钮、点击遮罩或 Esc 关闭，关闭后焦点返回入口。缩放窗口保留图鉴选择和生成结果。图鉴标签支持左右方向键、Home 和 End 切换。

选中项优先于描述中对应的要求：风格控制笔触与材质，排版控制构图与文字层级，单色主题控制配色（覆盖风格或排版示例中的其他颜色）。未选择的类别由描述决定。生成期间选择器暂停编辑。

图鉴数据和预览来自 [yang0/handraw-style](https://github.com/yang0/handraw-style)，与子模块锁定提交保持一致。图片打包在应用中，浏览选项不依赖网络；Rust 内置完整选项规范，校验编号后将规范与描述一起通过 stdin 传给 Codex。4000 字限制仅适用于用户描述。实际图像对规范的遵循程度取决于本地生图模型。

更新子模块后运行 `npm.cmd run catalog:sync` 同步 `src/data/generationCatalog.json`，并提交生成的数据。前端与 Rust 共用这份快照，测试会检查其与子模块的编号、图片和完整提示词一致；CI 会自动检出子模块。首次克隆也可以使用 `git clone --recurse-submodules`。

手动验收：切换各类 → 滚动到最后一张图并选中 → 搜索或滚动确认左侧摘要保留 → 点击摘要定位已选卡片 → 清除其中一类 → 提交生成 → 检查结果是否符合其余两类选择。另检查生成中不能重复提交或修改配置、失败保留旧图和描述，以及全部不选和只选一类；在 1659px、1100px 和 390px 窗口下检查布局、预览面板开关、Esc、Tab 焦点限制和连续滚动。

### Codex 生图准备

在运行 Handraw 的同一用户下安装并登录 [Codex CLI](https://learn.chatgpt.com/docs/codex-cli)：

```powershell
npm.cmd install -g @openai/codex
codex.cmd login
codex.cmd exec --help
```

安装后重启 Handraw，让应用获得新的 `PATH`。Windows 支持原生 `codex.exe` 和 npm 安装的 `codex.cmd`；其他系统从 `PATH` 查找 `codex`。
本地 Codex 还需配置可用的图片生成工具或技能及其所需凭据；仅安装 CLI 不保证具备生图能力。应用复用本机 Codex 的登录、模型和工具配置，不内置 API Key。
建议先在终端确认 Codex 能根据描述生成并保存 PNG。若使用的技能调用外部图像 API，请按该技能的说明配置凭据和网络访问。

后端使用[非交互模式](https://learn.chatgpt.com/docs/non-interactive-mode)，等价命令为：

```text
codex --ask-for-approval never exec --skip-git-repo-check --sandbox workspace-write --config sandbox_workspace_write.network_access=true --color never -
```

每次在独立临时目录执行，提示词通过 UTF-8 标准输入传入，要求 Codex 将实际生成图片保存为 `result.png`。不会将提示词拼进 shell 命令，也不会关闭 Codex 文件沙箱；允许联网，以便生图技能访问图像服务。需要交互授权的工具调用会失败，应用会展示 CLI 的错误摘要。
Rust 在后台线程等待，最多运行 10 分钟；Windows 超时会终止包含 npm 启动器在内的进程树。PNG 校验通过后以 data URL 返回前端，无需开放任意本地文件读取权限。
提示词最多 4000 个字符，图片文件最多 20 MB，解码缓冲区最多 64 MB。生成目录在请求结束时清理，生成成功后自动保存到本地图库；保存失败时保留预览与待保存数据，关闭应用前可重试或导出。

### 本地图库与导出

顶部可切换「创作工作台 / 我的图库」。原图与缩略图写入并提交 SQLite 后才计为已保存。保存失败会暂停后续生成，保留暂存图片及清单，支持重试保存与导出；可明确确认「放弃此图暂存」，不会将其标成已入库。若暂存磁盘也无法写入，结果只能保留在当前进程内存中，界面提示立即导出，并阻止带着未处理结果退出。

每次快速生成或计划确认创建一个独立照片组。每张最多等待 10 分钟，整组没有共用的 10 分钟限制。相同提示词的两次执行不会合并；失败位置保留原序号，重试不会改变组 ID 或目标张数。至少一张成功保存的照片才让组进入普通图库；没有成功照片的任务保留在「草稿与任务」。

图库按组的生成开始时间倒序排列，每页九组。卡片显示封面、最多三张缩略图、已保存照片数、可编辑的组标题、收藏和异常状态；待保存照片不计入照片总数。搜索匹配组与照片的标题、标签、原始提示词，结果仍为组卡片，显示匹配数量；打开时优先选择匹配照片，仍可切换浏览全组。组收藏与单图收藏相互独立，提供「收藏的组」「含收藏照片的组」两种筛选，可组合使用。

每张照片的详情保留大图、原始描述、三类配置及完整规范、实际提交提示词、图鉴内容 SHA-256 版本、尺寸、格式、文件大小和创建时间，可修改该图的标题与标签。工具版本从 `codex --version` 的有效输出记录，读取失败或超时则留空；当前生成接口未返回可验证的模型名称，因此模型字段留空，不从本机凭据或整份配置推测。

「复用创作」回填当前照片的描述与配置；已有编辑时先确认。未更换的选项继续使用旧作品保存的完整规范，即使新版图鉴已移除或修改该选项；更换后的选项使用当前图鉴。再次生成会创建新组，并记录来源组和来源照片。复用条件不保证再次生成完全相同的图片。

「删除此图」移入最近删除，删除封面后自动选择下一张有效照片，删除最后一张后该组不再出现在普通图库。「删除整组」一次删除当前有效照片；「恢复整组」仅恢复这次整组删除涉及的照片，保留此前单独删除的状态。单图仍可在最近删除中恢复或确认永久删除。

「导出此图」打开系统保存对话框，默认定位用户的图片文件夹；可同时导出包含提示词和生成条件的 `.txt` 说明。「导出整组」选择文件夹后创建一个独立子目录，按组内顺序导出当前视图中的全部照片及各自的说明（包含来源组信息），支持待保存照片。取消对话框不会写入文件；已有同名说明文件时需选择新的文件名，避免静默覆盖。导出途中发生磁盘错误会明确报错，已完成的文件保留在该子目录。

旧图库首次打开时，先取得进程锁、识别结构并检查空间，用 SQLite backup API 创建包含已提交 WAL 数据的一致性备份，再在事务内升级到结构版本 1。单图旧库每图补组，已有分组库保留组 ID 和成员关系；不重新编码或移动原图。未知结构、损坏 JSON 或更高版本会停止写入；迁移失败事务回滚，可重试或打开备份位置。历史组标为 legacy，历史生成中状态标为中断，不自动调用模型。

图库根目录由 Tauri `app_local_data_dir()` 解析。当前应用标识为 `com.walkskysu.handraw`，Windows 默认目录为 `%LOCALAPPDATA%\com.walkskysu.handraw\`：

```text
gallery.db                 SQLite 索引与生成元数据（不含图片 Base64 或工具凭据）
images/<ID>.png             新任务原始图片（历史路径保持不变）
thumbnails/<ID>.webp       最大 480 × 480 缩略图
staging/                   持久暂存图片与尝试清单，提交后清理
backups/                   升级前一致性数据库备份与校验清单
gallery.lock               进程锁，防止多个窗口同时清理和写入图库
```

数据库只保存受控相对文件路径。启动顺序为版本迁移、暂存与任务恢复、原图和缩略图检查。缺原图保留元信息，缺缩略图从原图重建；无法确认归属的文件原地保留并提示，不自动删除。迁移记录、原始 JSON 和顺序修复摘要保存在数据库中。

迁移备份不包含图片字节，也不会自动清理。完整备份请先关闭应用并复制整个目录。不要直接降级运行旧程序；恢复旧版本需匹配的数据库备份与文件集，并先备份当前数据。图库与导出使用受限的 Rust 命令，不向前端开放任意本地文件读取能力。

文字规划使用独立的 3 分钟超时、JSON Schema 与固定最终消息文件，禁用继承的用户工具配置、图片能力和 shell；不解析控制台日志为计划，不执行返回的命令或路径。结构错误最多修复一次。需要支持 `exec --output-schema --output-last-message --ignore-user-config` 的 Codex CLI；不支持时保留草稿并显示错误。规划结构校验不代表事实已核查。实现边界及验收记录见 [多图生成验收](docs/testing/multi-image-generation.md)。

图库验收：生成 → 确认已保存 → 关闭并重新打开 → 搜索/收藏 → 查看详情 → 复用并生成新作品 → 导出图片及说明 → 删除/恢复 → 确认永久删除。保存失败、写入回滚、启动恢复、分页、导出和历史规范复用由新增 Rust/前端测试覆盖；真实系统保存对话框仍需在桌面环境验收。

常见问题：

- **未找到 Codex / 无法启动**：检查 `PATH` 和 `codex.cmd exec --help`，安装后重启应用。
- **执行失败**：根据界面错误摘要检查 `codex.cmd login`、网络及工具配置。
- **模型要求更新 Codex**：遇到 `requires a newer version of Codex`（例如使用 `gpt-6-astra` 时）错误，弹窗会提示在终端运行 `npm.cmd install -g @openai/codex@latest`，升级完成后重启 Handraw 并重试。
- **未输出 result.png**：Codex 未实际生成文件；确认当前模型和生图工具可用，并支持保存 PNG。
- **超时 / 图片过大或损坏**：缩短描述或要求较小尺寸后重试。

无需 Rust 的浏览器预览：

```powershell
npm.cmd run dev
```

访问 `http://127.0.0.1:1420`。页面明确标注「浏览器预览」，可编辑提示词，但生成按钮禁用；只有桌面应用能调用本地 Codex。
开发端口固定为 `1420`，被占用时会报错；修改时需同步修改 `vite.config.ts` 和 `src-tauri/tauri.conf.json`。

## 测试与构建

```powershell
# 一次性运行前端组件与 IPC 适配测试，不依赖 Rust 或桌面窗口
npm.cmd test

# 浏览器布局回归测试（首次运行先安装 Chromium）
npx.cmd playwright install --no-shell chromium
npm.cmd run test:layout

# TypeScript 检查及前端生产构建（输出 dist/）
npm.cmd run build

# Rust 命令单元测试，需要完整桌面开发环境
npm.cmd run test:rust

# 编译 Windows 调试应用，不生成安装程序
npm.cmd run tauri -- build --debug --no-bundle

# 编译发布版本并生成 NSIS 安装程序
npm.cmd run tauri -- build
```

安装程序输出到 `src-tauri/target/release/bundle/nsis/`。首次构建会下载 Rust 依赖及相关打包工具，需要联网。
PowerShell 使用 `npm.cmd` 可避免 `npm.ps1` 被执行策略拦截；其他系统可使用 `npm`。

前端测试覆盖浏览器限制、空/过长输入、真实 Tauri JS API 的模拟 IPC、等待状态、重复提交保护、失败重试、图片替换、显示失败、错误弹窗开关与关闭后焦点、版本升级提示及文本转义。jsdom 中模拟原生 dialog API；焦点限制与 Esc 关闭需在桌面 WebView 中手动验收。
Rust 测试使用本地假 CLI 子进程，覆盖标准输入原样传递、PNG 返回、退出码、无图片输出、找不到程序、超时回收、图片校验及 Windows 带空格路径的 `.cmd` 启动器。测试不调用付费模型，也不需要 Codex 登录。
模拟 IPC 和假 CLI 测试不等于实际模型或 WebView 的端到端测试。

`.github/workflows/ci.yml` 在 `windows-latest` 上执行前端测试、类型检查、Rust 测试和桌面编译。
手动验收：完成 Codex 生图配置 → 启动 `tauri dev` → 确认显示「桌面应用」→ 输入「一只窗边的水彩小猫」并提交 → 确认等待时不能重复提交、完成后显示真实图片 → 修改描述再次生成 → 确认预览更新。再检查断网/未登录时的错误及重试，并调整窗口大小检查布局。
窗口位置验收：分别启动开发版和打包后的桌面应用，确认主窗口首次显示时位于屏幕正中央；拖动窗口后关闭并重新启动，确认再次居中。使用多显示器或不同显示缩放比例时也检查居中位置。此行为由 Tauri 的 `app.windows[].center` 原生配置控制，需要在真实桌面环境中验收。

## 更新发布版本

在项目根目录执行（版本号不带 `v` 前缀）：

```powershell
npm.cmd run version:set -- 0.2.4
```

该命令同步 `package.json`、`src-tauri/tauri.conf.json`、`src-tauri/Cargo.toml` 和 `package-lock.json`，并在 `src-tauri/Cargo.lock` 存在时更新其中应用自身的版本。不会升级依赖、提交代码、创建标签或推送；不需要联网。支持 `0.2.4-beta.1` 等 SemVer 版本。

运行 `npm.cmd run test:version` 可在临时目录中验证版本同步、非法输入和锁文件处理，不改变项目版本。

检查差异并完成测试后，将版本文件一起提交，再创建与版本一致的标签（例如 `v0.2.4`）并推送。已发布的旧标签不会随版本文件修改而更新。

## 项目结构

```text
src/
  App.vue                首页、输入状态与错误反馈
  main.ts                Vue 入口
  styles.css             手绘风格与响应式布局
  services/imageGeneration.ts  生图 IPC 及输入校验
tests/                   Vitest + Vue Test Utils 测试
src-tauri/
  src/lib.rs             异步 Rust 命令注册
  src/generation.rs      Codex 进程、图片读取及测试
  src/gallery.rs         SQLite 图库、文件保存、恢复及导出
  src/main.rs            桌面程序入口
  capabilities/          主窗口权限
  icons/                 应用图标及 SVG 源文件
  tauri.conf.json        窗口、开发地址、安全策略和打包设置
```

新增桌面能力时在 Rust 中定义并注册命令，在 `src/services/` 中封装调用，再由 Vue 组件使用。仅在需要插件能力时扩展 capability 权限。
项目不包含绘图编辑器；本地图库数据独立于应用安装目录保存。
