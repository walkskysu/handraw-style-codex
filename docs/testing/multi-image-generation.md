# 多图生成实现与验收

对应 Issue #18 / 设计 v1.0。自动验收不依赖账号，不产生生图费用。

## 实现边界

- `migrations.rs` / `schema.sql`：版本 0 两类旧库到版本 1，一致性备份、空间预检、事务迁移、原始 JSON 与修复摘要。锁覆盖 Store 生命周期；任何恢复写入之前检查版本与结构。
- `planning.rs`：草稿修订、完整计划版本、数量与结构边界、内容摘要。反馈失败不替换旧计划；历史选择复制新版本。
- `jobs.rs`：串行持久队列、幂等确认、固定条目/尝试身份、停止、恢复、重试保存。关系与状态有显式列及外键/唯一索引，完整配置和计划采用 JSON。组/照片统一写入并由同事务触发器同步旧 JSON 镜像；照片读取以关系列为准。

其他标量（草稿模式、输入、反馈、计划摘要/确认时间、任务数量/停止标志、尝试错误/校验摘要）使用 SQLite `STORED` 生成列，从完整记录产生只读投影，避免可独立改写的双重事实来源。状态/更新时间索引用于任务查询。结构仍只有一个 `photo_groups` 表。
- `creation.rs`：后台任务与 IPC，单个模型锁，提交后轻量通知。`plan_create` 的可选 `base_plan_id` 同时承担修订；`generation_continue` 的可选 `item_id/attempt_no` 承担指定位置重试。首次 `draft_update` 不传 ID 即创建草稿。
- `CreationFlow` / `PlanPanel` / `JobPreview`：双模式、反馈/版本、按序占位、单张预览、订阅后快照、2.5 秒查询兜底、草稿与任务入口。重复/乱序通知不会倒退状态。
- `gallery/groups`：至少一张已保存且可用图片才进入普通图库；单图和整组操作、封面选择、确认计划导出、来源删除提示。缺图记录不被删除。

`generated` 和 `saved` 分开。明确放弃未入库结果使用 `save_status=discarded`，保留生成事实与用户操作说明，不计已保存/待保存，也不会自动重画。文件先持久暂存再入库，提交后才清理。无法持久化时仍保留内存预览和导出入口，阻止退出。

## CLI 验证与发布前人工验收

已检查本机 `codex exec --help`：支持 JSON Schema、固定最终消息文件、只读沙箱及忽略用户配置。规划参数依据 [官方配置 schema](https://developers.openai.com/codex/config-schema.json)；使用固定参数和 UTF-8 stdin，Windows npm shim 不接收拼接的用户命令。子进程模拟测试验证输出协议、非 JSON 控制台日志、缺文件、过大结果、失败退出、独立超时和字面提示词传递。

2026-10-27 在此自动化环境尝试真实文字规划，CLI 在模型调用前返回 `Error finding codex home: Could not find home directory`。因此**真实账号规划/生图及系统文件对话框尚未完成验收**，不得将模拟通过表述为真实模型链路已通过。需在正常登录的桌面用户会话中完成：

1. 快速单图实际生成与导出，检查实际图片、工具版本和完整提示词。
2. 自动规划两张，反馈两次，确认前无图片调用；确认后第一张完成即出现，第二张继续。
3. 第二张执行时停止，检查当前完成后停止；关闭重开，再手动继续。
4. 模拟磁盘不可写，导出或修复后重试保存；仅内存结果在退出前必须处理。
5. 用真实历史图库副本升级，核对备份位置、组成员与图片，再验证整组/单图导出、收藏、删除恢复。

数据库备份不包含图片；不支持直接降级旧程序。自动化只验证结构与恢复行为，不宣称模型内容事实正确或视觉一致性有保证。
